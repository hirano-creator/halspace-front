# TENQ 運用手順書

- 版: 0.1（第1段階・ドラフト）／作成日: 2026-10-22
- 本書の手順のうち、本番の設定変更・データ変更を伴うものは担当者とオーナーの確認のうえで行う

## 1. 日常運用

| 頻度 | 作業 | 担当 |
| --- | --- | --- |
| 毎日 | ダッシュボードで未点検・未対応異常・期限超過を確認 | 工場長・設備担当 |
| 毎週 | 期限超過の異常の担当・期限を見直す | 工場長 |
| 毎月 | Cloudflare ダッシュボードで Workers のエラー率・CPU、D1 のサイズ、R2 の容量を確認し、本書末尾の記録表に書く | システム管理者 |
| 毎月 | バックアップの取得と保管確認（§3） | システム管理者 |
| 四半期 | 復元テスト（開発環境へ復元できるか） | システム管理者 |
| 年 1 回 | 保存期間を過ぎた記録の棚卸し（§5）、権限の棚卸し（退職者・異動者） | システム管理者・品質管理 |

## 2. ユーザー管理

- 新規利用者: Space.app 管理画面でアカウント作成と利用アプリ `tenq` を付与 → TENQ のユーザー管理で TENQ ロールと所属工場を設定
- 異動: 所属工場を変更（過去の記録は点検当時の工場のまま残る）
- 退職・端末紛失: [security.md §8](security.md) の手順。TENQ で利用停止 → Space.app でパスワード再発行・アプリ付与の解除
- ロールの変更は監査ログに残る。年 1 回、ロール一覧を出力して工場長が確認する

## 3. バックアップ

| 種類 | 方法 | 保持 |
| --- | --- | --- |
| D1 の自動復元地点 | D1 Time Travel（無料 7 日・有料 30 日。任意の時点へ戻せる） | プランによる |
| D1 の定期エクスポート | `npx wrangler d1 export tenq-db --remote --output=tenq-db-YYYYMMDD.sql` を月 1 回（自動化は第7段階で検討） | 保存先・保持期間は §7 で確定。個人情報を含むので社外・個人 PC に放置しない |
| 写真（R2） | R2 はオブジェクトを複数拠点に保存している。誤削除対策として、TENQ は写真を論理削除のみとし実体を消さない | 保存期間まで |
| 設定・コード | Git（halspace-front）。マイグレーションファイルも含む | 恒久 |

エクスポートファイル（`.sql`）は Git に入れない（`.gitignore` 済み）。

## 4. 復旧手順

### 4-1. 誤操作・不具合でデータが壊れた（直近 7 日以内）

1. 影響範囲を確認（監査ログで時刻と対象を特定）
2. 現在の状態をエクスポートして退避
3. `npx wrangler d1 time-travel info tenq-db` で復元地点を確認
4. **まず開発環境に**エクスポートを読み込み、復元結果を確認
5. オーナー承認後、`npx wrangler d1 time-travel restore tenq-db --timestamp=<時刻>` で本番を復元
6. 復元後に入った正しい記録（手順 2 の退避分）を必要に応じて再登録し、経緯を記録する

### 4-2. 7 日より前のデータが必要

月次エクスポートを開発環境の新しい D1 に読み込み、必要な記録を確認・抽出する。本番への書き戻しはオーナー承認のうえで個別に行う。

### 4-3. 障害時の代替運用（TENQ が使えない）

- 原因の切り分け: Cloudflare のステータス、Railway（halspace-api）のステータス、tenq-api のログ（`npx wrangler tail tenq-api`）
- **点検は止めない**: 紙の点検表（TENQ の帳票印刷から作った予備様式）に記入し、復旧後に設備担当者が代理入力する。代理入力は「紙からの転記」として備考に残し、紙は保管する
- 危険度の高い異常は TENQ の状態にかかわらず、社内の連絡ルールで責任者へ連絡する

## 5. 保存期間の管理

- 保存期間は システム設定 `retention_years`（既定 5 年、品質管理担当者が確定する）
- 期間を過ぎた記録は「保存期間超過」一覧に出るだけで、**自動では削除しない**
- 削除する場合の手続き（案）: 品質管理担当者が対象期間を承認 → 削除前にエクスポートを長期保管先へ → 開発環境で手順を確認 → 本番で実施 → 実施記録を残す。手続きが決まるまで削除機能は実装しない

## 6. 監視

- Workers: エラー率・CPU 時間・リクエスト数（Cloudflare ダッシュボード → Workers & Pages → tenq-api）
- D1: DB サイズ（無料枠 500 MB の 70% で有料化の検討を開始）
- R2: 容量（無料枠 10 GB の 70% で検討）
- halspace-api: /auth/me の失敗が続く場合は Railway 側を確認（2026-09-30 に、アプリと DB は正常なのに Railway の入口だけが詰まった前例がある）
