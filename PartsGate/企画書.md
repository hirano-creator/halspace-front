# PARTS GATE 企画書

バーコードを使った部品照合・出荷確認システム

- 作成日: 2026年11月5日
- 状態: 設計段階（画面の方向性を検討中。開発は未着手）
- 最初の導入先: 株式会社ヒラノ（将来はほかの会社にも提供）

---

## 1. 背景

現在、ミスミから届く注文データ（CSV）と出荷する部品の照合は、Google スプレッドシート「部品確認シート」で行っています。

- CSV をシートに貼り付け、置場（例: 55）とミスミ納期で絞り込んで、置場ごとの確認表を作る
- 部品のバーコードを読み、該当する行に「チェック者」と「チェック時間」を記録する
- チェックが済んだ行は緑色になる

この方法は手軽ですが、次の点に限界があります。

- 複数の PC で同時に読み取ると、同じ部品の二重チェックや記録の食い違いを防ぎにくい
- 読み取りの失敗（注文にない部品、二度読み）が記録として残らず、後から原因を追えない
- 日別・担当者別・置場別の作業量や、エラーの傾向を分析しにくい
- ほかの会社に同じ仕組みを提供できない

## 2. 目的

注文データと実際の部品をバーコードで照合し、**誤出荷・部品の取り違え・出荷漏れを防ぎます**。あわせて、次のことを実現します。

1. 誰が、いつ、どの部品を確認したかを、すべて記録する
2. 置場（向け先）ごとに、確認の進み具合を一目で分かるようにする
3. 記録を蓄積し、作業量やエラーの傾向を分析できるようにする
4. 最初から複数の会社で使える作りにし、会社どうしのデータを完全に分ける

## 3. 対象範囲

| 範囲 | 内容 |
| --- | --- |
| 今回作るもの | 注文 CSV の取込、バーコード照合、作業担当者の記録、置場・納品先の管理、読み取り履歴、ダッシュボード・分析、CSV 出力、会社ごとのデータ分離 |
| 今回は作らないもの | 出荷完了の確定（当面は照合まで）、契約・請求・決済の機能 |
| 利用する場所 | 出荷場の PC（USB バーコードリーダー）、管理者のスマートフォン（状況の確認） |

## 4. 業務の流れ

```
① ミスミから注文 CSV が届く（1日1回）
② 管理者が PARTS GATE に CSV を取り込む（内容を確認してから確定）
③ 作業者がログインし、自分の名前（担当者）を選ぶ
④ 部品のバーコードを読む → システムが注文データと照合
⑤ 結果を色・文字・音で表示し、担当者と日時を記録
⑥ 置場ごとの残りを見ながら作業を進める
⑦ 管理者が履歴・進み具合・分析を確認する
```

## 5. 主な機能

### 5-1. CSV 取込

- ミスミの CSV（Shift-JIS）をそのまま取り込める。UTF-8 にも対応
- 取り込む前に、**新規・更新・変更なし・エラー・要確認**の件数と中身を表示し、確認してから確定する
- 同じ CSV を2回取り込んでも、注文が二重に登録されない
- 置場マスターにない置場コードは自動登録せず、「要確認」として知らせる
- 取り込み直しても、読み取りの記録は消えない
- 元の CSV ファイルは保存し、取込の履歴（日時・担当者・件数）を残す

### 5-2. バーコード照合（最重要）

- USB バーコードリーダーで読むだけで照合する（マウス操作はほぼ不要）
- 結果は色・アイコン・文字・音の4つで表示する

| 結果 | 表示 | 意味 |
| --- | --- | --- |
| 正常 | 緑 ✔ | 注文データと一致した |
| 読み取り済み | 黄 ⚠ | すでに確認済みの部品をもう一度読んだ（誰がいつ読んだかも表示） |
| 要確認 | 黄 ⚠ | 注文はあるが、置場の未登録などで確認が必要 |
| 未登録 | 赤 ✖ | 注文データにない番号 |

- 複数の PC で同じ部品を同時に読んでも、「正常」になるのは1回だけ（判定はサーバー側で行う）
- 通信が切れて同じ読み取りを再送しても、記録は1件だけ
- ラベルが汚れて読めないときは、番号を手で入力できる（手入力したことは記録に残る）

### 5-3. 担当者の記録

- ログイン用のアカウントと、実際に作業する担当者を分けて管理する（1台の PC を複数の人が交代で使えるようにするため）
- 担当者を選ばないと読み取れない。画面には担当者名を常に表示する
- 担当者名を後から変えても、過去の記録は当時の名前で残る

### 5-4. 履歴・分析

- すべての読み取り（エラーも含む）を記録し、日付・担当者・商品コード・置場・結果などで検索できる
- 記録は削除しない。訂正するときは、元の記録を残したまま訂正の記録を追加する
- ダッシュボード: 本日の注文件数、照合済み、未確認、エラー、担当者別・置場別の件数
- 分析: 日別・月別の読み取り数、担当者別の作業量、得意先別・商品別・置場別の注文数、エラーの発生状況
- CSV で出力できる

### 5-5. マスター管理

- 置場・納品先・担当者は、会社ごとに自由に登録・編集できる（プログラムに固定値を入れない）
- 使われている置場は削除せず「利用停止」にする
- ヒラノの初期の置場:

| 置場コード | 置場名 |
| --- | --- |
| 0052 | 西日本（※確認中） |
| 0053 | 東日本 |
| 0055 | 中日本 |
| 0056 | 西日本第二 |

## 6. 画面

### 6-1. 方向性（決定）

5つの案を比較し、**「C 伝票チェック」案を、今の部品確認シートに近い形に改訂したもの**を採用する方向です。

- 置場（向け先）ごとのタブに分け、タブに「済み / 全体」と進み具合を表示する
- 一覧の列は今のシートと同じ（グローバル番号、メーカー出荷日、ミスミ納期、出荷方法、商品コード、置場、数量、個別重量、商品重量、チェック者、チェック時間）
- チェック済みの行はシートと同じ緑色にし、チェック者と時間が自動で入る
- 別の置場の部品を読むと、その置場のタブに自動で切り替わり、「置場が違います」と知らせる
- 下段に、置場ごとの件数・数量合計・重量合計を表示する
- 「未チェックだけ」「未チェックを上に並べる」で、残りの部品をすぐ探せる
- 画面上部に**読み取りの状態**を表示する（緑＝読み取りOK、赤＝止まっている、灰色＝担当者の変更中）
- スマートフォンでは、置場を切り替えながら未チェックの部品を確認できる（閲覧用）

## 7. 実際のデータで確認したこと

ミスミの注文 CSV（81列・89行のサンプル）を分析し、次のことを確かめました。

- 文字コードは Shift-JIS。顧客注文番号に半角カナが含まれる
- **グローバル番号は1行ごとに異なり、バーコード用グローバル番号と同じ値**。照合にはこの番号を使う
- 同じ伝票に同じ商品コードの行が複数あることがある。商品コードではなく、グローバル番号で行を見分ける
- 置場は4桁（0053 など）で記載されている
- お届け先名は空欄で、代わりに直送先コード・直送先名が入っている
- 直送先コードは別々の得意先で同じ値が使われることがある。得意先コードと組み合わせて見分ける

ヒラノとの確認で決まった業務ルール:

| 項目 | 決定 |
| --- | --- |
| ラベルの枚数 | CSV の1行（グローバル番号1つ）につき1枚。1回読めばその行は照合完了 |
| 置場コード | CSV と同じ4桁で登録する |
| CSV の頻度 | 1日1回 |
| 出荷完了 | 当面は作らない（照合まで） |

## 8. システム構成と費用

### 8-1. 構成

HaLSpace のアプリ基盤「Space.app」のアプリの一つとして作ります。ログインや会社・利用者の管理は Space.app のものを使うので、新たにアカウントの仕組みを作る必要がありません。2段階認証もそのまま使えます。

```
出荷場の PC（USB リーダー） ・ スマホ
        │
        ├─ ログイン ────→ Space.app（既存。追加費用なし）
        │
        └─ PARTS GATE ──→ Cloudflare（無料プラン）
                           ├ 処理（Workers）
                           ├ データベース（D1）… 注文・読み取り記録・マスター
                           └ ファイル保管（R2）… 元の CSV・バックアップ
```

設備点検アプリ「TENQ」と同じ構成です。TENQ は2026年10月から無料プランで本番稼働しているので、その作りと運用の経験を活かせます。

### 8-2. 費用

**月額0円**で運用できる見込みです（ヒラノ1社の場合）。

| 項目 | 無料プランの上限 | 見込み |
| --- | --- | --- |
| 処理の回数 | 1日10万回 | 1日数百〜数千回 |
| データ量 | 500MB | 1年約50MB（10年で上限に届く見込み） |
| ファイル保管 | 10GB | 年数十MB |
| サーバー（Railway） | — | 既存のものを使うだけで、増やさない |

無料で運用するための工夫:

- PARTS GATE 専用の Cloudflare アカウントを作り、TENQ と無料枠を取り合わないようにする
- 重い処理（CSV の解析など）は画面側で行う
- ダッシュボードは集計済みの表から表示し、データベースの読み込みを減らす
- 大量データでの性能テストは手元の PC で行う

無料プランは、上限を超えても請求は来ません。その代わり、一時的に使えなくなります。ほかの会社に提供してデータが増えた段階で、有料プラン（月5ドル程度）への切り替えを検討します。

## 9. 安全性

- **会社どうしのデータを完全に分けます**。どの会社のデータかはログイン情報からだけ判断し、画面から送られた会社の指定は信用しません。ほかの会社のデータが見えないことを、全機能について自動テストで確かめます
- 管理者と一般の利用者で、できる操作を分けます（CSV 取込やマスター変更は管理者だけ）
- 読み取りの記録と、重要な操作の記録（監査ログ）は書き換え・削除できない仕組みにします
- 毎日のバックアップに加えて、月1回データ全体を保存します。実際に復元できることもテストします

## 11. 確認が必要な事項

| 番号 | 内容 | 案 |
| --- | --- | --- |
| 1 | バーコードリーダーが実際に送る文字（ラベル1枚をメモ帳に読ませた結果） | 実機で確認 |
| 2 | 置場「0052 西日本」が正しいか（サンプル CSV に出てこない） | 確認 |
| 3 | 輸出区分 E（MISUMI USA 向け）を国内分と同じ画面で扱ってよいか | 同じ画面で区別して表示 |
| 4 | PARTS GATE 専用の Cloudflare アカウントを誰のメールで作るか | 確認 |
| 5 | 未登録の置場の行を取り込むか | 置場を登録するまで取り込まない |
| 6 | メーカー出荷日が今日でない部品を読んだとき | 「要確認」にする（設定で切替可） |
| 7 | 納品先マスターにない納品先の扱い | 取込画面からまとめて登録できるようにする |
| 8 | 確認済みの部品の内容が、翌日以降の CSV で変わったとき | 上書きせず「要確認」で知らせる |
| 9 | 読み取り用 PC のログイン方法 | PC ごとにアカウントを作り、作業者は担当者を選ぶ |
| 10 | 独自ドメインが必要か | 当面は不要 |
| 11 | シートのチェック者「ロス」は担当者の名前か | 確認 |
| 12 | 一覧に得意先・お届け先の列を加えるか | 確認 |
| 13 | 伝票ごとの進み具合（例: 3 / 9 済）を残すか | 確認 |

## 12. 想定される課題と対策

| 課題 | 対策 |
| --- | --- |
| リーダーの出力形式がまだ分からない | 読み取り値の整え方を設定で変えられるようにし、実機で確認してから決める |
| Space.app のサーバーが止まるとログインできない | ログイン確認の結果を短時間保持する。長時間止まった場合に紙で確認する手順を運用マニュアルに書く |
| 他社の CSV は列の名前が違う | CSV の列の対応を会社ごとの設定にする |
| 10年でデータ量が無料の上限に届く | 上限に近づいたら知らせ、古いデータの移動か有料化を判断する |
| ブラウザで音が鳴らない場合がある | 担当者を選ぶ操作のときに音を有効にしてから、読み取り画面に移る |
