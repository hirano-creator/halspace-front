## 2. 開発環境

- 専用の Cloudflare アカウント（Q-4）に開発用の `partsgate-db-dev` / `partsgate-files-dev` / `partsgate-api-dev` を作る（すべて無料枠）
- 普段の開発・テストはローカル（`wrangler dev --local`、D1 は手元の SQLite）。**遠隔の開発環境での負荷テストはしない**（TENQ の停止事故の再発防止）
- ログインはローカルの solid-api（Laragon）か、開発用の簡易ログイン（`APP_ENV=dev` のときだけ有効）

## 4. バックアップと復元（概要。手順は STEP 9 で README と運用マニュアルに書く）

| 方法 | 頻度 | 保存先 | 用途 |
| --- | --- | --- | --- |
| D1 Time Travel | 自動 | D1（無料は 7 日分） | 直近の誤操作からの復元 |
| 差分バックアップ | 毎日（Cron Trigger） | R2 `backups/daily/<日付>/<表>.ndjson` | 前回以降に追加・更新された行。長期保存 |
| 全体の書き出し | 月 1 回（手作業、`wrangler d1 export`） | R2 `backups/full/<年月>.sql` と手元 | 全体の復元 |

復元は「全体の書き出し」を空の DB に入れ、その後の差分を日付順に適用する（`scripts/restore.mjs`）。

## 5. 想定される課題

| 課題 | 対策 |
| --- | --- |
| リーダーの出力形式が不明（Q-1） | 整形ルールを設定にし、STEP 6 の前に実機で確認 |
| 無料プランの CPU 10ms | 重い処理は画面側。主要 API の CPU 時間を毎回測る |
| D1 の読み取り上限 | 専用アカウント・集計表・索引必須・性能テストはローカル |
| halspace-api（Railway）が止まるとログインできない | `/auth/me` の 60 秒キャッシュ。長時間止まった場合は紙での確認に切り替える手順を運用マニュアルに書く |
| Space.app のトークンが無期限 | PARTS GATE 側で 12 時間の再ログイン |
| 他社の CSV は列名が違う | 列の対応表を会社の設定に持つ |
| 10 年で D1 の 500MB に届く | 400MB で警告を出し、古い年度の R2 移動か有料化を判断 |
| ブラウザの音が鳴らない（自動再生の制限） | 担当者選択のボタン操作で音声を有効化してから読み取り画面へ |
